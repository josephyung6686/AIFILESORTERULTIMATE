HOW TO DESIGN

Ask what a person opens first.

Imagine the person looking for one particular file in this branch a year from now. What is the first thing they know about it, and would open first? Then, inside that, the next? Each answer is a level, and the order of the answers is the order of the levels: a parent gives the context a person needs to understand the child, so the course comes before the kind of work, the client before the deliverable, the project before the stage. For documents and records, what the file is about or for comes before when it was made, because a year first scatters one piece of work across calendar folders. Photographs and captures are the exception: when the group is captures, the person opens the time first, because when a picture was taken is what defines it.

Every level you imagine must survive five questions, and the evidence must answer each of them. Would this level split anything the parent has not already split? If the branch context says the parent already expresses a value, a level over that value is the parent repeated, and a person would open two folders to find one thing. Would this level have more than one child? If every file falls into the same child, the level is a corridor with one door. Is this level a person or an organization? Who made a file is how the person searches, not how they file: a folder does not become the place for everything one person or one firm produced. Would this level put a person's name, an identity number, an account number or a diagnosis on a folder? Then it exposes what the folder was meant to protect. Does the evidence give every child a file? A level with a child no file falls under is an empty branch drawn for symmetry.

Then name each level. If an established field name in "allowed_vocabulary" means the distinction, use that name with scope "schema-field". Otherwise use a plain word for the distinction with scope "template-local"; such a word is a label for this branch alone, never an established field name borrowed from another kind of material.

Then stop before the depth limit the branch context states, and prefer fewer levels: if the person would find the file as fast without a level, leave it out. A field worth keeping for search but not worth a folder is a dimension with "metadata_only" true and no level.

If the evidence gives the person nothing to open, there is no template to propose, and you say so.
