# 01 — Tool-generated producer / creator strings (P6 suppression list)

- **list_id**: tool_producer_strings
- **version**: 1.0
- **authored**: 2026-08-20
- **owner**: P6
- **consumer**: the §2.2/§2.3 producer-creator discount rule, tier 1 (Suppression) — a match produces **no fact in any field** and one `unresolved` row with `reason = discounted_tool_metadata`
- **match_field**: `observation.raw_value` where `location.zone == metadata` and the `field`-kind segment's label is one of the property names below
- **normalization for matching**: Compare against the raw value with Unicode NFC applied and leading/trailing whitespace stripped, **for comparison only**. P4 RAW-1/RAW-2 keep the stored `raw_value` byte-for-byte untouched; this normalization exists inside P6's matcher and never writes back.
- **boundary rule**: A `prefix` entry fires only when the character following the matched prefix is end-of-value or one of ` `, `\t`, `,`, `;`, `:`, `/`, `(`, `)`, `-`, `_`, `.`, `®`, `™`, `©`. It never fires when the next character is a letter or a digit. This is the word-boundary rule that stops `Pages` matching `Pagesmith` and `iText` matching `iTextbook`. `exact` entries compare the whole normalized value.

## Design basis

- §2.2: "PDF metadata should be treated as supporting evidence, not as truth. Author and creator fields may be stale, generic, or generated by a tool rather than a person, so a value such as `python-docx`, `Mozilla/5.0`, or a browser-generated producer string should not be mistaken for meaningful content." — the three settled seeds are entries `tps-python-docx`, `tps-ua-mozilla-5`, and the browser class (`tps-ua-*`).
- P5 SPEC E1: "They are emitted verbatim (the raw value is never discarded, §2.8) at `zone = metadata` with `reliability: direct` — `direct` describes the **slot**, not the value's usefulness."
- P5 SPEC E1 / M4: "There is no marker on the observation. P5 sets no suppression flag and invents no field: the producer/creator discount rule is P6's."
- P6 SPEC, *Suppression*: "It is not downgraded to `possible`; a tool name is not a weak clue about the document, it is a fact about the software."
- P6 SPEC, *Demotion*: any value NOT on this list "may populate an authorship role field (§3.8 `authored_by`) and nothing else" — so a miss here is a contained recall loss, never a wrong destination (§3.8 makes every authorship field `destination_eligible = FALSE`).
- P2 SPEC A4 adversarial case: "generic author metadata (`python-docx`, `Mozilla/5.0`, browser producer strings) | metadata trust | metadata retained as supporting evidence only | a facet, group, or destination dimension keyed on creator identity".

## Rules this list obeys

1. **No human author names.** No entry may match a string that is a plausible personal name. This is the rule that keeps a Creator of `Jane Chen` off the list; it is also why bare `Adobe`, bare `Prince`, bare `Canon`, and bare `Nikon` are refused below rather than matched.
2. **Exact by default.** `prefix` is used only where the tool appends a version and the false-positive analysis is written into the row. `regex` is used only where the tool token sits in the middle or end of the value (`Quartz PDFContext`, browser UA tokens).
3. **P5 never sees this list.** It is injected into P6 only; nothing here may become a module-level constant inside `src/extractors/` (P5 PLAN Global Constraints / Task 20).
4. **Suppression, not demotion.** A match writes no fact in any field, including `authored_by`. A near-miss is not downgraded — it takes the ordinary demotion path.
5. **No dates.** Nothing here parses or matches a date; §3.10 is P6's separate deferred row.

## Injection

P6 receives this list as data at construction — `FactResolver(..., tool_producer_strings=load('01-tool-producer-strings.json'))` or the P1-namespaced configuration object equivalent. It is **not** imported as a module-level constant, and it is never imported anywhere under `src/extractors/`: P5 emits the producer value verbatim with no flag (M4), and Task 20's runtime-introspection guard fails if any producer string appears in an `extractors` module namespace.

## Coverage note

v1 covers the PDF producer/creator engines, Office and Office-compatible writers, browser user-agent strings, and the imaging tools that stamp EXIF/PNG `Software` — the four families §2.2 and §2.6 actually name. It deliberately does **not** enumerate camera firmware strings, scanner-model strings, or per-vendor MFP producer strings: those are open-ended vendor sets whose members change per model, and entry `tps-bare-version` already catches the bare-version-number form most of them take in a `Software` slot. Camera **filename** patterns are catalogue 04, not here. Growth path: add a row when a real corpus surfaces a string, with the same six evidence columns.
